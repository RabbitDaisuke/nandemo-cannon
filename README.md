# なんでもキャノン — Godot 4.7.2

大砲から物を投げ、火・水・氷・爆発を使って置き場を作り、青いエリアへ積むブラウザ向け物理ゲーム。ゲーム本体はGDScriptとGodotの2D物理で実装し、**Godot 4.7.2 stable / WebAssembly / WebGL 2 / 単一スレッド**へ固定した。エンジンのソースコードをクローンしなくても、公式エディタと同じ版のExport Templatesで開発・出力できる。

## 収録内容

- 277種類の小物。食品、おもちゃ、家電、森や家の模型に加え、CPU・メモリ・OSなどのパソコン部品、本、原寸大のなんでもキャノンを収録。100種類は上限にしない。
- 45種類のマップで各15投。42はコンピューター、43はほんやさん、44はなんでもおさらい、45はなんでもキャノン2。
- 独立した砲身の回転軸、砲口に追従する射出位置、反動、選択輪郭。台座は回転しない。
- 発射音「オノマトペ 衝撃01」は[OtoLogic](https://otologic.jp/) / [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。原本MP3を再生音量25%で使用し、起動画面にクレジットを大きく表示。プレイ中は表示しない。詳細は`web/licenses/otologic.txt`。
- BGMは[BGMer](https://bgmer.net/)の「陽気な週末」「おめざのじかん」「いったりきたり」。トップは無音でクレジットを表示し、プレイ開始後に再生。初期音量2.5%、ゲーム下部のBGMボタンと音量スライダーで変更でき、localStorageに保存する。iOS向けにもGainNodeで音量を制御する。
- 個別の当たり判定、燃焼と消火、有限燃料、耐爆確率、衝突と継続荷重による破損、水流と反射、氷床、車輪の接地、凍結したゴムの脆化。
- 小物・マップは16bit風SVG。大砲2案・ロゴ・日本語フォントは画像生成し、`.mjs`でパーツ分割・切り詰め・lossless WebP化。フォントはひらがな全86字と反復記号、カタカナ、HUD文字・記号を含む246字。小物を拡大するために透明余白を増やさない。

## 遊び方

起動画面の「はじめる」を押す。画面中央のプレイ領域を上下へドラッグすると角度、左右へドラッグすると火力が変わる。大砲の小さな絵を狙う必要はなく、マウスと1本指で同じ操作ができる。第1面の十字矢印で操作を案内する。短いクリック／タップを離すと発射し、ドラッグを離しただけでは発射しない。上部の得点・説明、下部の調整欄や各ボタンからは発射しない。大砲に重なる絵が装填中の物体で、「つぎ」はその次の物体。

画面下のスライダーでも調整できる。キーボードは上下で角度、左右で火力、Spaceで発射、Rで再挑戦、MまたはEscでマップを開く。マウスはゲーム面の左クリックと中クリックでも発射できる。メニュー操作では発射しない。装填物は実際の投射物と1:1で表示する。砂場となんでも実験室は一覧から自由選択でき、選ばなければ既定の順番で進む。カウンターと原寸大の大砲は自由選択の一覧・検索結果から隠すが、指定ステージや全カタログ抽選には残る。寸法・得点・検索索引は維持する。きゅうきょくじっけんしつも自由選択でき、未選択ならシード抽選を使う。合計15投は変わらず、残り0個では物体選択とプレイ中のマップを開けない。結果画面からはマップへ移動できる。

タッチは2本以上の指で全ゲームを1〜2.5倍へ拡大でき、指の中心にある場所を基準に移動する。2本指になった時点で大砲のドラッグやUIの押下を取り消し、全指を離すまでゲーム操作を抑止する。拡大中も物理演算は続く。マップは15件ずつ3ページに分かれ、「まえのページ」「つぎのページ」で切り替える。

「もの」一覧の上部で名前とタグを部分一致検索できる。ひらがなとカタカナは同じ読みとして扱い、「かみなり」「カミナリ」はかみなりまほうだけ、「りょうり」「ごはん」は料理、「みず」は水への対処に使える関連物を表示する。検索欄は漢字と未対応文字を除き、入力できる文字だけを残して案内を表示する。右側に直近2件を置き、押すと再検索できる。一覧を開き直すたびに検索欄は空へ戻り、履歴は起動中のメモリだけに保持する。タグは独立した`data/item-search-index.json`へ手書きで登録し、追加・改名時は[モノ追加手順](docs/ADDING_ITEMS.md)を読む。検索タグは物理やゲーム分類へ使用しない。
シード画面には「このシードで やりなおす」と「べつのしーどにする」を横並びで置く。前者は同じ投射リストを再現し、後者は現在のステージを新しいシードで最初から始める。画面を開いただけでは物理演算を止めない。

「とくてん」は0.5秒ごとに現在の配置から計算する。有効な物体の全当たり判定が青いエリアに入った場合だけ基本点と高さボーナスを付ける。高さは基準床から物体中心までの縦方向の距離で、16pxごとに10点。放置時間や横方向の距離では増えない。ボーリングの初期配置ピンはエリア内に残ると1本−100点で、高さボーナスは付かない。抽選枠があるステージではサイズ・高さ・性質を合わせた候補から選び、導入道具は固定する。第21面は全カタログから15個を抽選する。同じシードでは同じ投射リストになる。もの・マップ・シードを開いても飛行、火、水、時計は進み、開閉で速度や時間倍率を変えない。15投後の確定時は、開いていたメニューを結果画面へ置き換える。結果確定後と非表示タブの自動停止は別扱い。

結果画面を重ねる前に、確定スコア入りのゲーム画面をJPEGとして撮影し、メモリへ保持する。黒い横長の「X でポスト」で文章・スコア・ゲームURL入りの投稿画面を開き、「がぞうをほぞん」でJPEGを保存できる。Xの投稿画面へ画像は直接添付できないため、保存した画像を自分で添付する。ファイル共有に対応する環境では「がぞうつきでシェア」も使える。

残り0個ではプレイ中のマップボタンもグレーアウトし、キー操作からも開かない。結果画面のマップ移動は利用できる。装填物には名前を表示し、ステージの説明は得点の下、軌道は暗い縁のあるピンクで表示する。
候補数が15を超えるステージは、候補の異なるIDから15種類を抽選してランダム順にする。候補数は22に固定しない。`shuffleQueue: true`では15個のリストや抽選枠の出力順も混ぜられる。いずれもステージのシードで再現し、指定のない既存面の固定順は保つ。ひとざとの建物・山・道路は通常のモノに近い模型サイズで、自由選択からの除外は設けない。

通常の爆弾・花火などは実際の当たり判定の50%以上が水に浸かると不発化し、基本100点の得点物になる。乾燥・再加熱で復活しない。耐水ばくだん2種は水中でも起爆する。流出後の厚さ1px以下の薄い水は一定時間後に蒸発する。

スポンジは24単位（水差し1個分）、タオルは12単位（水風船1個分）まで、自分に接触した水を吸収する。満杯になると吸水を止め、重さは最大2倍になる。近くを通っただけの水や、凍った水は吸わない。ビーチの水は静水で、吸った分だけ水面が下がる。川の流れは残し、水に浸かる実際の割合に応じた抵抗と浮力を物理演算へ適用する。

音源はゲーム開始後、必要になった曲を初回だけ丸ごと取得する。3曲を一巡ごとにシャッフルし、周回の境目でも同じ曲を連続させない。取得中のPromise・圧縮MP3のBlob・blob URLをページ起動中のメモリに保持し、繰り返し再生、オン・オフ、ステージ変更、トップへ戻って再開しても1曲1ダウンロードを維持する（再読み込みは新しい起動）。全曲保持時の圧縮音源は約9.5MBで、全曲をPCMへ展開しない。初回の配信元は自前`audio/bgm/`と`https://daisukedaisuketeam.github.io/nanndemo/audio/bgm/`から50%ずつで選び、HTTP・通信・CORS・本文取得失敗時だけ他方を1回試す。再生拒否やデコードエラーでは再取得しない。ミラーには音源ZIPを公開ルートへ展開し、`audio/bgm/088.mp3`・`415.mp3`・`073.mp3`を配置する。`web/audio/bgm/`はGodot PCKと起動時取得ZIPから除外し、Pagesへ別配置する。ZIP単体のゲームはBGMなしでも動き、音楽付きの自己完結版は`out/standalone/`一式を使う。音源の権利・加工情報は`web/licenses/bgmer.txt`。

## ビルド

入口はリポジトリ直下の`./build.sh`に統一した。Node.js 22以上とBashを用意し、リポジトリのルートで実行する。

```sh
./build.sh
```

引数なしは`bundle`。検索・物理・進行の5種類の検証、Node画像生成、公式Godot 4.7.2によるWeb exportを順に実行する。

|コマンド|用途・出力|
|---|---|
|`./build.sh` または `./build.sh bundle`|検証とWeb export。`out/standalone/`と`out/runtime/godot/4.7.2/`を作る|
|`./build.sh check`|Godot headlessで検索・body・cannon・hazard・gameの検証を実行する|
|`./build.sh preview`|NodeだけでSVG素材と保存済みゲーム状態から確認画像を生成する|
|`./build.sh bgm`|ミラー配置用の音源3曲・クレジット・配置説明を`out/packages/nandemo-cannon-bgm.zip`へまとめる|
|`./build.sh runtime`|公式テンプレートからランタイムを抽出し、`out/engine/`を作る|
|`./build.sh source`|検証と公式Web exportを行い、エンジンを除いた`out/game/`を作る|
|`./build.sh standalone`|結合済み`out/standalone/`からPLiCy・itch.io投稿用の音楽付きZIPを作り検証する。再export・公開はしない|
|`./build.sh deploy`|結合済み`out/standalone/`をZIP化してローカル検証し、ZIPを公開して`dist/`を作る|
|`./build.sh pages`|`bundle`→`deploy`を順に実行する|

Godotの自動セットアップはLinux x86_64のみ対応する。ほかのOS、または既存エディタを使う場合は、公式4.7.2の実行ファイルを`GODOT_BIN`で指定する。同じ版のExport Templatesも必要。WindowsではGit BashなどのBash環境から実行する。

```sh
GODOT_BIN=/absolute/path/to/godot ./build.sh
```

Godotエディタで編集する場合は`project.godot`を開き、F5でゲーム全体を実行する。npmの`godot@0.7.10`は別のNodeイベント処理パッケージなので使用しない。エンジン本体のソースクローンも不要。

## GitHub ActionsとPages

GitHub Pagesの公開版は広告なしで維持する。PLiCy・itch.ioへの投稿用は、同じActions実行のArtifactsにある **`nandemo-cannon-standalone-4.7.2`** をダウンロードする。Actionsが付ける外側のZIPを展開し、中の **`nandemo-cannon-standalone-4.7.2.zip`** を投稿先へアップロードする。従来の`nandemo-cannon-web-4.7.2`はPagesのエンジン配信用で、BGMを含まないため投稿には使わない。

投稿用ZIPは直下に`index.html`があり、公式GodotのJS・未圧縮WASM・音声worklet、ゲームPCK、画像、BGM全3曲、元のライセンスを同梱する。ゲーム内に広告を追加せず、起動・音楽はアップロード先の相対パスだけを参照する。外部ミラーを使わず、音楽は遅延取得・ランダム再生・起動中1曲1取得のまま。投稿先サービスが表示する広告はそのサービス側の設定による。共有ボタンは埋め込みCDNのURLを使わない。`https://html5.plicy.net/`ではパスの数値IDを正規表現で取り出し`https://plicy.net/GamePlay/ID`へ変換する（通信不要）。ほかの投稿先では既存の公開ゲームURLを使う。

投稿版だけに大きな「画面をクリックしてください」の案内を出す。背景は黒86%を重ね、初期画面をうっすら残す。カーソル検出・タップ・キー操作で消え、同じページでは再表示しない。入力やゲームの演算は止めない。`web/input-hint.mjs`の`STANDALONE_INPUT_HINT`はソースではfalse、Actionsが`STANDALONE_INPUT_HINT: "1"`を渡して投稿コピーだけtrueへ切り替える。手元で無効にする場合は`STANDALONE_INPUT_HINT=0 ./build.sh standalone`。Pages版のフラグはfalseのまま。添付のOpenclipart SVG原本と出典は`docs/third-party/openclipart/`に保存し、画面内クレジットには追加しない。

PLiCy（`https://html5.plicy.net/`）の永続データはすべてlocalStorageへ保存する。全ステージの最高得点は`nandemo-cannon.progress.v1`、BGM設定は既存の`nandemo-cannon.bgm.v1`。Godotの`persistentPaths`を空にしてIndexedDBのマウント自体を無効にする。保存領域が利用できない場合はその起動中のメモリだけに保持し、IndexedDBへは戻さない。Pages・itch.io・ネイティブの既存得点保存経路は維持する。音源キャッシュ、リザルトJPEG、選択ページ・検索など元々セッション限定のデータは、これまでどおりメモリだけに保持する。

[itch.io](https://itch.io/docs/creators/html5)では種類を「HTML」にし、ZIPをブラウザで再生するファイルとして指定する。表示サイズの目安は960×540、モバイル対応・全画面を必要に応じて設定する。[PLiCy](https://plicy.net/ToolFAQ/GODOT)ではGodotのWeb出力として同じZIPをアップロードする。単一スレッドのためSharedArrayBuffer／COOP・COEPは不要。HTTP(S)配信向けであり、ZIPを展開して`file://`で直接開く形式ではない。各サービスへの実アップロード・ブラウザ動作は別途確認する。

既存のruntime/sourceの2成果物を結合した後、`./build.sh standalone`で`out/portal/`と投稿ZIPを作り、upload-artifactへ保存してから従来どおりPagesへデプロイする。ジョブとGodotビルドは増やさない。投稿ZIPは`dist/`や`cdn-assets`へ追加せず、Pagesの配信量も増やさない。ローカルでは`./build.sh bundle`→`./build.sh standalone`。生成元の`out/standalone/`は変更せず、`out/portal/`だけでローダーを通常WASMへ切り替え、JSの拡張子を`.js`にする。ZIP展開の完全性・容量制限・深い配信パス・HTTP経由の起動シェル（描画スタブ）・公式WASMコンパイル・音源の存在をNodeで検証する。

ゲーム本体と小さな公式JS・音声workletはGitHub Pagesで配信する。重いWASMは完全版ZIPから取り出す。公開リポジトリは[RabbitDaisuke/nandemo-cannon](https://github.com/RabbitDaisuke/nandemo-cannon)。`Deploy Pages` workflowはmainへのpushと手動実行で起動する。Sitesは使用しない。

1. ソースを`RabbitDaisuke/nandemo-cannon`のmainへpushする。
2. リポジトリの **Settings → Pages → Source** を **GitHub Actions** にする。
3. mainへのpushで起動した**Deploy Pages**を確認する。手動では**Actions → Deploy Pages → Run workflow**を実行する。

`runtime`と`source`の2jobが並列に`./build.sh runtime`と`./build.sh source`を実行し、`web-runtime`と`web-game`をupload-artifactへ渡す。両方の完了後、deploy jobがdownload-artifactの`pattern: web-*`、`merge-multiple: true`で`out/standalone/`へ結合し、`./build.sh deploy`を実行する。

deployはエンジンを含むWeb全体をZIPのstore方式でまとめ、`unzip -t`と内容の整合性をローカルで確認し、同じZIPを`dist/downloads/`へ置く。`tools/publish-archive.mjs`は標準の`GITHUB_TOKEN`で、同じリポジトリの`cdn-assets`ブランチへZIP、ルートの`LICENSE`、Godotの原本ライセンス、管理用README・マーカーだけを保管する。展開済みWeb一式はブランチへ重複保存しない。deploy jobに`contents: write`が必要で、mainのソースと指定ミラー側のリポジトリは変更しない。

`runtime.json`の`archives`には`./downloads/nandemo-cannon-web-4.7.2.zip`と、ユーザー指定の`https://daisukedaisuketeam.github.io/nanndemo/downloads/nandemo-cannon-web-4.7.2.zip`を設定する。起動ごとに50%ずつの確率で片方を選び、通常はZIPを1回だけ取得する。HTTP・通信・整合性エラー時だけ、もう片方を1回試す。同時要求は同じPromiseを共有する。自前ZIPはサイズとSHA256を照合し、指定ミラーの旧ZIPは取り出した公式WASMのSHA256で互換性を確認する。配信先への事前プローブは行わない。

`out/standalone/`は圧縮ランタイムを同梱した結合出力（BGMは既定でミラー併用）。`bundle`の`out/runtime/godot/4.7.2/`と`runtime`の`out/engine/runtime/godot/4.7.2/`には、公式のJS3ファイル、`godot.wasm.gz`、manifest、原本ライセンスを生成する。Pages配信用ZIPは`out/packages/nandemo-cannon-web-4.7.2.zip`。復号後のWASMは公式原本と同一。未圧縮WASMを同梱する投稿用は別の`out/portal/`とstandalone ZIPである。

Pages側はゲーム資産に加え、未改変の公式JS・音声worklet約290KBを`runtime/godot/4.7.2/`で配信する。WASMは選ばれたZIPから取り出したgzipを`DecompressionStream`で展開してGodotへ渡す。結合直後の出力は同梱gzip、PLiCy・itch.io投稿版は同梱の未圧縮WASMを使う。詳しくは`docs/BROWSER.md`。

2ミラー構成は[Actions実行39953964261](https://github.com/RabbitDaisuke/nandemo-cannon/actions/runs/39953964261)で全job成功・Pages公開済み。以降の変更の公開結果は該当コミットのDeploy Pages実行を参照。
