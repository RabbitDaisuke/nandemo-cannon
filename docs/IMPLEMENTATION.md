# 実装の分担と座標

## エンジン構成

Godot 4.7.2のCompatibilityレンダラーを使う。GDScriptのゲームコードをWeb exportのPCKへ格納し、単一スレッドの公式WebAssemblyランタイムから実行する。ゲームをJavaScriptの描画・物理処理へ置き換える構成ではない。Node.jsはビルド、素材の分割・変換・画像確認、配布ファイル検証に使う。

開発者と後続AIの入口はリポジトリ直下の`./build.sh`。検証だけは`./build.sh check`、画像確認は`./build.sh preview`。Actionsは`runtime`と`source`を並列実行し、2成果物を結合して`deploy`を呼ぶ。`pages`は手元から同じ処理を順に行う入口。補助コードは`tools/`に置く。

公開時は圧縮WASMを含む完全版ZIPをPagesの`downloads/`へ置き、`cdn-assets`ブランチには同じZIPとライセンス・管理ファイルだけを保管する。クライアントは現在のPagesとユーザー指定Pagesミラーを起動ごとに50%ずつで選び、通常1回のZIP取得でWASMを取り出す。同時要求はPromiseを共有し、HTTP・通信・整合性エラー時だけ他方を1回試す。配信先への事前プローブは行わない。設定と配布先は`BROWSER.md`を参照。

物理は120Hz、基準画面は960×540。キャンバスはウィンドウに合わせて拡大する。画面比が違う端末ではゲーム領域の比率を維持するが、各SVG素材自体の外周へ余白を追加して縮小表示することはしない。

|ファイル|責務|
|---|---|
|src/game.gd|ステージ、15投、日本語UI、装填物と次の物体、採点、メニュー、乱数、進行保存、発射音、結果JPEG|
|src/game_catalog.gd|JSONの読み込み、地形の静的剛体生成、凹多角形の凸分解|
|src/cannon.gd|台座と回転砲身、砲口の座標、クリックとドラッグ、反動|
|src/throw_body.gd|小物の実剛体、複数fixture、衝突破損、荷重、車輪、靴底|
|src/hazard_system.gd|燃焼、火炎・冷却噴射、爆発、花火の導火線、耐性、燃料、消火と融解|
|src/liquid_field.gd|有限水量、水源、水滴、流れ、抵抗と浮力、傘反射、凍結したセル|
|src/effect_sprite.gd|寿命付きのSVGフレームアニメーション|
|web/share.mjs|メモリ上の結果画像、JPEG保存、X intent、対応環境でのWeb Share|

地形はcollision layer 1、動く小物はlayer 2。図柄から毎フレーム自動生成する衝突判定ではなく、カタログのrectangle・circle・polygonを読み込む。背景は静的で、見た目の壁と本当に衝突する壁は地形データで明示する。地下穴、台座の空洞、橋の隙間、奈落、レストランの凹んだ皿は実際の地形形状で表現する。

## SVGと物理の整合

小物の元座標は128×128。SVGの切り詰め後viewBoxと`pivotSource`を別々に保持する。小物の絵もfixtureも`(元座標 - pivotSource) × worldScale`を共通で使う。多角形の分解後も元fixture番号を保持し、車輪・靴底・傘の判定番号を失わない。

Godotは小物SVGをインポート時にテクスチャへ変換する。原稿は編集可能なSVGのまま残す。マップのSVGに含まれるパターンを確実に保持するため、20マップは`.mjs`とsharpでPNGへ変換したものを実行時に読み込む。追加40物体は`tools/extend-stage-content.mjs`に原稿・fixture・ステージ定義を持ち、ドーナツは描画の透明穴と8個の凸fixtureを対応させる。

大砲・ロゴ・日本語UI文字は画像生成した原稿から切り出したlossless WebP。大砲は2候補から黒鉄のB案を採用し、砲身と架台を独立させる。フォントはひらがな全86字と反復記号、カタカナ、HUD文字・記号を統合した246字で、`assets/font/generated-coverage.json`を正確な収録表とする。旧SVGフォントはフォールバック用に残す。日本語の全文字を含める方式ではないため、新しい表示文字にはグリフも追加する。原稿と処理は`GENERATED_ART.md`を参照。

`data/ui-ja.json`に157物体と20ステージのかな表示名、各面の案内文を持つ。ゲーム画面は日本語とし、正式な漢字の`nameJa`は共有文などで使う。表示名を変えても物理や保存に用いるIDは変更しない。

## 状態と削除

小物は固体の剛体に、燃焼・濡れ・凍結・燃料などの状態を重ねる。火・水・氷の効果を別の描画専用画像に留めず、破損、摩擦、流れ、得点へ接続する。通常の炎は数秒で終わる。コンロだけはステージの明示的な継続火源であり、鍋による遮熱と火源自体の消火を分ける。

破損・燃え尽き・奈落などの削除はワールドの`destroy_actor()`へ集め、当たり判定と採点対象から外す。破片や炎のアニメーションは有限寿命を持つ。水滴最大96、液体セル最大256、効果スプライト最大80として、永久増殖する粒子を避ける。無制限の流体シミュレーションではなく、遊べる量の有限水と既設の川を組み合わせる。

通常爆発の破壊確率は`clamp(強度 × (1 - 耐爆値) × 距離減衰, 0, 1)`。耐爆値1なら破壊されず、0でも爆心からの距離で変わる。爆発ごと・物体ごとに乱数を1回引く。船の練習木箱だけは有効爆風3回で壊れる保証ルールにする。箱同士で爆風を遮らない一方、地形は遮蔽する。炎は鍋などの剛体も遮蔽する。

## 進行と拡張

`data/catalog.json`は人が編集するカタログ、`data/objects-manifest.json`は描画と物理が直接読む定義。`data/physics.json`は素材・挙動ごとの値を記録する。現在は157種類。新しい物を増やすときはSVG、カタログ、manifestのfixtureと物理属性、必要なら投射キューを更新する。種類数を配列上限にしない。

`data/stages.json`は全20面に15個のqueueを持つ。火・水・爆弾の前提順序があるためシャッフルしない。初期配置はqueueと別枠で、15は投射物の数。第16面はレストラン、第17面はガレージ、第19面は祭り、第20面は「なんでも実験室」。従来の氷床を第18面へ移したことは`assignment`に実装上の仮定として残す。氷の判定は`iceFloor`や表面領域を使い、番号へ固定しない。分類としてのkinematic・undecidedは将来用で、現在の投射物へ未実装挙動を混ぜない。

上下ドラッグで角度、左右ドラッグで火力を調整し、第1面では十字矢印で案内する。スライダー・方向キーも使える。装填中の物体と「つぎ」の物体を別々に表示する。発射音はOtoLogicのCC BY 4.0音源をMP3原本のまま音量25%で再生し、Web上部にクレジットを置く。

SEEDはステージごとの疑似乱数系列を再現する。異なるブラウザやCPUで剛体の浮動小数結果まで完全一致する保証はしない。最高得点はローカルへ保存し、ゲームサーバーへの自動送信は行わない。

得点確定後、HUDを更新し、結果オーバーレイを作る前の描画フレームをJPEGへ変換する。画像はメモリに保持し、撮影できなければ以前の画像を再利用しない。headless実行では描画待ちと撮影を省略する。黒い横長のXボタンは正式ステージ名・スコア・URL入りのintentを開き、JPEG保存とWeb Shareのファイル共有は別操作にする。X intentには画像を直接添付できない。Web Shareはファイル共有の可否を確認して表示し、ユーザーが共有先を選ぶ。

Godotの物理・進行・入力検証の最新件数と結果は`previews/body-checks.json`、`hazard-checks.json`、`cannon-checks.json`、`game-checks.json`を参照する。Nodeでの画像確認やheadless成功を実ブラウザQAとして報告しない。
