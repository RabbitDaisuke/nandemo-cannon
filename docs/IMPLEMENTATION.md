# 実装の分担と座標

## エンジン構成

Godot 4.7.2のCompatibilityレンダラーを使う。GDScriptのゲームコードをWeb exportのPCKへ格納し、単一スレッドの公式WebAssemblyランタイムから実行する。ゲームをJavaScriptの描画・物理処理へ置き換える構成ではない。Node.jsはビルド、SVGの画像確認、配布ファイル検証にだけ使う。

開発者と後続AIの入口はリポジトリ直下の`./build.sh`。検証だけは`./build.sh check`、画像確認は`./build.sh preview`、GitHub Actions上の公開は`./build.sh pages`。補助コードは`tools/`に置くが、CIから個別スクリプトを組み合わせる必要はない。公開時は公式WASMを実際の`.wasm.gz`ファイルとして同じ公開リポジトリの`cdn-assets`ブランチへ保存し、実コミットSHAを固定したStatically URLを使う。内容のSHA256とCORSを確認できない場合は公開を止める。

物理は120Hz、基準画面は960×540。キャンバスはウィンドウに合わせて拡大する。画面比が違う端末ではゲーム領域の比率を維持するが、各SVG素材自体の外周へ余白を追加して縮小表示することはしない。

|ファイル|責務|
|---|---|
|src/game.gd|ステージ、15投、入力UI、物体生成と削除、採点、メニュー、乱数、進行保存|
|src/game_catalog.gd|JSONの読み込み、地形の静的剛体生成、凹多角形の凸分解|
|src/cannon.gd|台座と回転砲身、砲口の座標、クリックとドラッグ、反動|
|src/throw_body.gd|小物の実剛体、複数fixture、衝突破損、荷重、車輪、靴底|
|src/hazard_system.gd|燃焼、火炎・冷却噴射、爆発、耐性、燃料、消火と融解|
|src/liquid_field.gd|有限水量、水源、水滴、流れ、抵抗と浮力、傘反射、凍結したセル|
|src/effect_sprite.gd|寿命付きのSVGフレームアニメーション|

地形はcollision layer 1、動く小物はlayer 2。図柄から毎フレーム自動生成する衝突判定ではなく、カタログのrectangle・circle・polygonを読み込む。背景は静的で、見た目の壁と本当に衝突する壁は地形データで明示する。地下穴、台座の空洞、橋の隙間、奈落は実際の地形形状で表現する。

## SVGと物理の整合

小物の元座標は128×128。SVGの切り詰め後viewBoxと`pivotSource`を別々に保持する。小物の絵もfixtureも`(元座標 - pivotSource) × worldScale`を共通で使う。多角形の分解後も元fixture番号を保持し、車輪・靴底・傘の判定番号を失わない。

GodotはSVGをインポート時にテクスチャへ変換する。原稿は編集可能なSVGのまま残す。マップのSVGに含まれるパターンを確実に保持するため、20マップは`.mjs`とsharpでPNGへ変換したものを実行時に読み込む。文字は自作SVGからBMFontのアトラスへまとめる。標準の日本語フォント全体を含める方式ではないため、現在の収録文字以外の新しい日本語をUIへ追加するときはグリフも追加する。

## 状態と削除

小物は固体の剛体に、燃焼・濡れ・凍結・燃料などの状態を重ねる。火・水・氷の効果を別の描画専用画像に留めず、破損、摩擦、流れ、得点へ接続する。通常の炎は数秒で終わる。コンロだけはステージの明示的な継続火源であり、鍋による遮熱と火源自体の消火を分ける。

破損・燃え尽き・奈落などの削除はワールドの`destroy_actor()`へ集め、当たり判定と採点対象から外す。破片や炎のアニメーションは有限寿命を持つ。水滴最大96、液体セル最大256、効果スプライト最大80として、永久増殖する粒子を避ける。無制限の流体シミュレーションではなく、遊べる量の有限水と既設の川を組み合わせる。

通常爆発の破壊確率は`clamp(強度 × (1 - 耐爆値) × 距離減衰, 0, 1)`。耐爆値1なら破壊されず、0でも爆心からの距離で変わる。爆発ごと・物体ごとに乱数を1回引く。船の練習木箱だけは有効爆風3回で壊れる保証ルールにする。箱同士で爆風を遮らない一方、地形は遮蔽する。炎は鍋などの剛体も遮蔽する。

## 進行と拡張

`data/catalog.json`は人が編集するカタログ、`data/objects-manifest.json`は描画と物理が直接読む定義。`data/physics.json`は素材・挙動ごとの値を記録する。新しい物を増やすときはSVG、カタログ、manifestのfixtureと物理属性、必要なら投射キューを更新する。117という数を配列上限にしない。

`data/stages.json`のqueueは15個。火・水・爆弾の前提順序があるためシャッフルしない。初期配置はqueueと別枠で、15は投射物の数。ステージ17〜20のqueueはnullのままにし、未定のゲームルールを勝手に埋めない。分類としてのkinematic・undecidedは将来用で、現在の投射物へ未実装挙動を混ぜない。

SEEDはステージごとの疑似乱数系列を再現する。異なるブラウザやCPUで剛体の浮動小数結果まで完全一致する保証はしない。保存するのはステージごとの最高得点で、サーバーへプレイ情報を送る仕組みはない。
