# モノを追加・改名するときに読むこと
検索用の手書き索引は `data/item-search-index.json`。モノを追加するときは、この文書を読み、同じIDの `items` エントリーを人が判断して追加する。既存の全モノにも個別のタグ配列を置く。検索索引は検索専用であり、ゲーム分類・材質・物理挙動・得点・抽選枠・ステージ配置・解放条件には絶対に接続しない。
## 名前とタグの役割
今後の追加名はかな表記で、既存品と区別できる短い名称にする。説明や容器の長い注釈を名前に詰め込まず、別名は手書き検索タグへ置く。文字数の強制上限や切り捨ては実装しない。従来の長い名称を一括改名しない。
正式名と画面表示名は実行時に名前の部分一致検索へ取り込む。ひらがなとカタカナは同じ読みとして比較する。名前をタグへ丸ごと複製する必要はない。タグにはプレイヤーが探しそうな用途・見た目・別名を手で付ける。例として「スポンジ」には `みず`・`きゅうすい`・`すいとる`、「冷却噴射器」には別名の `れいとうじゅう` を付ける。
`りょうり` と `ごはん` は調理済みの料理や主食を探すために同じ対象へ付ける。食器と調理器具には `しょっき`・`ちょうりどうぐ` を使い、料理の検索を道具で埋めない。菓子には `おやつ`・`おかし`、果物には `くだもの`、飲み物には `のみもの` を付ける。すべての食べ物をまとめたい場合は `たべもの` を使う。パンケーキのように食事と菓子の両方で探すものには両方を付けてよい。
`みず` は水を出す物だけでなく、吸水・水をはじく物など、プレイヤーが水への対処で探す関連物にも手で付ける。`とくしゅ` は炎・水・氷・爆発・吸水・車輪などを探す入口として必要なモノにだけ付ける。これらのタグを付けても、モノの能力や物理設定は一切変わらない。
`かみなり` または `カミナリ` で表示するのは `lightning-orb`（かみなりまほう）だけ。電池・充電器・家電は雷を起こすモノではないため、電気の連想だけで雷のタグを増やさない。火炎放射器は名前そのものの `かえんほうしゃき` で検索できる。
## 手動編集の形式
IDは既存のモノのIDと一致させ、タグは読みで探せるひらがな・カタカナを使う。漢字、絵文字、フォント未対応文字をタグに使わない。各モノに有用なタグを最低1件、人が判断して付ける。名前の検索とタグの付与は別の処理であり、名前のためだけにタグを重複登録しない。
```json
{
  "version": 1,
  "items": {
    "lightning-orb": ["まほう", "ばくはつ", "とくしゅ"],
    "sponge": ["みず", "きゅうすい", "すいとる", "そうじ", "とくしゅ"]
  }
}
```
索引を生成スクリプトで再生成しない。`material`・`behavior`・ステージ番号・既存のゲーム分類からタグを推測して自動付与しない。逆方向にも参照させず、検索タグからゲーム分類や物理設定を決めない。検索の結果は表示候補の絞り込みだけに使う。ゲーム側の設定変更だけを理由に検索タグを自動変更しない。
## 追加・変更後の確認
モノの追加時は索引のID漏れ・余分なID・重複タグ・使用文字を確認する。改名時は表示名の自動検索を確かめ、旧名を残す必要がある場合だけ別名タグとして手で追加する。削除時は索引の該当IDも削除する。テストで索引の網羅性や構造を確認してよいが、不足タグをテストやビルドから自動補完してはならない。
追加したモノを名前・別名・用途で検索し、意図する対象だけが出ることを確認する。特に `かみなり`／`カミナリ` が雷魔法だけになること、`かえんほうしゃき` が火炎放射器になること、`りょうり` と `ごはん` が同じ料理を出すことを維持する。
検索欄は漢字を拒否し、収録フォントに対応した文字だけを受け付ける。一覧を開き直すと検索文字列は空へ戻す。直近2件は検索欄の右に表示し、押すとその語を再検索する。履歴と現在の絞り込みを同じ状態として扱わない。検索してもゲーム中の演算やモノの性能を変更しない。
## 初期配置物の得点
ステージの`preplaced`へ置くモノは`scoring: true`で通常の得点物にできる。指定しない・falseの場合は得点対象外。得点物は存命で実コライダー全体が得点範囲にある場合だけ基本点と高さ点を得る。`scorePenalty`がある場合は負点を優先し、高さ点は付かない。初期配置だから固定する、配置時の得点を永続加算する、検索タグから得点を決める実装にしない。
## 自由選択一覧からの除外
`objects-manifest.json`のモノに`catalogSelectable: false`を指定すると、自由選択の一覧・検索結果・履歴からの検索に表示しない。省略時は選択可能。検索インデックスは削除せず、材質・寸法・得点も変更しない。ステージに指定した発射リストや`randomCatalog`の抽選は引き続き使用できる。現在の対象は`counter`と`cannon-object`。生成元`tools/extend-late-content.mjs`にも設定を残し、再生成で解除されないようにする。
## 自由選択専用の追加
例外として`randomCatalogScope: "all"`を指定した全カタログ抽選では`selectionOnly`も抽選する。ランダム実験室ときゅうきょくちかしつが対象で、将来の追加品も自動的に候補へ入る。`selectable`は一覧表示可能品、未指定は従来の通常抽選を維持する。
`selectionOnly: true`のモノは自由選択一覧と検索で選べるが、`randomCatalog`の自動抽選には含めない。省略時は従来どおり抽選可能。`catalogSelectable`とは独立した設定で、カウンターなどの非表示物を抽選から除外するものではない。既存ステージの発射候補は書き換えず、同じシードの抽選順も維持する。明示したステージキューへの登録は可能だが、専用品を既存キューへ自動追加しない。
自由選択専用アセットの原稿は`tools/selection-food.mjs`と`tools/selection-tools.mjs`。`./build.sh selection-items`でSVG・PNG・lossless WebP・物体データ・確認画像を再生成する。検索タグはこの処理から読み書きせず、前述の手順で索引へ直接記述する。新しい表示名と正式名は両方かな表記にし、商標名やブランドロゴを描かない。通常のビルドは保存済みの生成物を使用する。
## 候補数と発射順
`queueOverrides: [{"shot": 6, "item": "strong-blast-wave-bomb"}]`は、抽選やシャッフルの後に指定投を置き換える。投数は1始まりの1〜15、同じ投数を重複指定しない。発射数を増やさず、任意の面・任意の物に使える。新規面だけ自由選択の追加物も抽選したい場合は`queuePolicy: "randomCatalog"`と`randomCatalogScope: "selectable"`を併記する。省略時の既存抽選とシードは変えない。検索タグはこれらの抽選へ使わない。
`queue`が15件なら従来の固定順で15投する。15件を超える場合は異なるIDを候補として15種類を重複なしで抽選し、順番もランダムになる。重複記述で確率を増やさず、候補に最低15種類を用意する。候補数22は第41面の構成にすぎず、エンジンの上限にしない。`shuffleQueue: true`は15件のリストや`queueSlots`の抽選結果の順番を混ぜたい場合に使う。ゲームの乱数器でシードを再現し、`Array.shuffle()`など別の乱数状態へ切り替えない。既存の`randomCatalog`は全カタログからの従来の抽選を保つ。

## ステージの表示順
内部idと配列位置は保存データ・乱数シードの識別に使うため、既存の面を並べ替えない。ナビゲーションは`sequenceGroup`（省略0）と`sequenceOrder`（省略id）の昇順にする。終盤に残す面はgroup100/200などをデータで指定し、HUD・マップ一覧・次ステージの移動は共通のカタログ関数を使う。通常面を追加するときに既存の終盤IDやステージ数をコードへハードコードしない。
