# 火・水・氷・爆発の実装

`src/hazard_system.gd`が火、燃料、凍結、爆発を管理し、`src/liquid_field.gd`が有限の水滴、水セル、水流領域を管理する。物体本体は`ThrowBody`の剛体を使い、表示はSVGアセットを読み込む。接触、遮蔽、水滴の反射にはGodotの実際の形状照会を使う。

## 火と燃料

火炎放射器は発射時から6秒で燃料が尽き、空の容器のSVGへ切り替わる。炎と噴流は6枚のSVGを毎秒12フレームで更新する。噴射方向は剛体の回転に追従し、5本の照会線で最初に当たった形状まで届く。壁、金属容器、フライパンなどの固体が炎を遮る。

燃える指定のある木箱、丸太、ゴミなどは一定時間燃えた後に消滅する。濡れ、凍結は着火を遅らせる。床にも燃焼領域があり、普通の床の炎は水で消えて、3秒の濡れ状態になる。熱源指定のコンロは継続する熱源として扱う。焚火と燃料ランタンは燃料の時間を1本だけ持ち、通常の燃焼寿命を重ねて減算しない。水や冷気で消火すると残燃料を終了し、消火後のSVGに替える。火炎放射器の内部燃料は水を浴びるだけでは失われない。

## 水と傘

水風船などは衝突時に指定量を一度だけ放出する。水入りの容器は継続荷重、爆発、容器の焼失でも中身を放出する。荷重の初期値は力7840の超過が0.4秒続く条件で、床の支持反力は除外する。放出済みのフラグを各経路で共有するため、同じ破損が重なって通知されても水を増やさない。水源タイルは毎秒の供給量と総供給量を持ち、上限まで放出すると止まる。水流領域は指定方向への力、水中抵抗、浮力を剛体へ与える。流されないテーブルは`flowResponse: 0`で水流からの押す力を受けないが、水中抵抗や濡れの対象にはなる。

水滴は移動前後を線分で照会する。傘は天蓋だけでなく、軸と持ち手を含む全当たり判定で水を反射し、傘自体には濡れを付けない。水セル間の移動と水滴からセルへの変換にも線分照会を使うため、セル幅より細い軸をすり抜ける判定にならない。タオルなどの吸水物は容量まで水を保持し、吸った比率に応じて質量が増す。

有限水は16pxのセルを最大256個、水滴を最大96個まで扱う。1セルの内部容量は4単位で、満杯になった水を単純な丸めで消さない。水滴をセルに移せない場合は残量を水滴に保持して再試行する。放出時に両方の上限へ達した場合の受け入れ拒否、画面外への排水、吸水物へ移った量を別々に記録する。`current_volume()`は現在の水滴と水セルの合計を返す。固定された川の水流領域は無限の背景水として別扱いで、川から作った氷の分は`region_drawn_volume`に記録する。これはゲーム用のセル近似であり、連続流体の圧力計算ではない。

## 氷と爆発

冷気は周囲を消火し、有限水と川の表面を8秒間凍らせる。凍ったセルには摩擦0.025の`StaticBody2D`を作り、融解時には当たり判定を外して水へ戻す。凍結・融解で元の水量を上書きしない。氷塊は熱を蓄積すると指定量の水へ変わり、濡れ状態でも融解できる。

爆発は爆心からの距離、爆発強度、0〜1の爆発耐性で破壊確率を計算し、爆弾と対象の組ごとに一度だけ乱数を引く。耐性1は確率0になり、耐性0は距離と強度によって確率が決まる。爆風の遮蔽は地形に限定し、積み上げた手前の木箱が奥の木箱を完全に守る状態を防ぐ。炎の遮蔽は引き続き物体も含める。船のチュートリアル木箱は、届いた爆発を3回受けて壊れる明示的な例外であり、同じ爆弾の再通知は数えない。

## 実行した検証

Godot 4.7.2のheadless実行で`tests/hazard_checks.gd`の37項目が成功した。実際の剛体、照会、SVGリソースを使い、6秒の燃料寿命と表示変更、丸太の燃焼、焚火、ランタン消火、水の一度きりの放出、床の消火、傘の天蓋・軸・持ち手の反射、水流と水中抵抗、金属容器の炎遮蔽を確認した。荷重試験では床に置いた水ボトルが内容物を保ち、質量12の木箱を載せると荷重破損が一度だけ起きて8単位を放出した。水タンクが爆発で壊れた場合の24単位、ボトルが燃え尽きた場合の8単位も確認した。結果は`previews/hazard-checks.json`に保存する。

9.75単位の水を複数セルへ入れて45回流した後も、現在量と排水量の合計は9.75単位を維持した。256個の満杯セルへ512単位を追加する上限試験では、水滴96個の上限を守り、現在量と明示的な受け入れ拒否量の合計は1536単位だった。さらに3.2単位の凍結・融解で量が変わらないこと、濡れた氷塊が5単位の水へ変わること、爆発耐性の両端、6個の木箱が3回目の爆発で壊れることを確認した。ブラウザを起動せずに行ったGodotネイティブの検証であり、Safari・Chrome・Firefox実機での描画や操作の検証は別途必要になる。
